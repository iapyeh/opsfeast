# Vault retention consumer

This bundled consumer implements [consumer contract 0.1.0](../../docs/retention-consumers.md). Its source is `builtin:vault`, ID `vault`, with default activation. It subscribes to observation creation/deletion and operation creation across recipe sources. It delegates current-state Markdown generation to `host_vault.rebuild`; `vault_content.build/render_observation` supplies the renderer. This separation lets explicit `vault rebuild` use the same application without manufacturing or acknowledging events.

Requirements: Python 3.11+, OpsFeast initialization dependencies, a namespace-enabled profile with valid hosts.yaml, writable local Vault output and retention read access. No network, SSHScript execution, model or Obsidian plugin is required. It consumes the installed public retention envelopes, including registered inventory-observations 0.1.0, host-values 0.2.0 and operation journals. Preserve partial/unknown values and identity evidence when extending presentation.

Observation rendering now provides six inventory sections and nested collection tables, readable capacity/duration units, visible partial/identity warnings and collection scope, plus a final labeled provenance disclosure instead of a Python origin dictionary or inventory JSON dump. General host-values use typed value/state/unit/meaning tables. The public retention data and the existing operation-journal presentation are unchanged. Readers without HTML disclosure support may show provenance expanded. See the [rendering contract and regeneration command](../../docs/host-vault.md#recipe-retention-and-markdown).

The consumer owns presentation titles: System inventory for inventory and human recipe-ID labels otherwise. Current page names use current-<title-slug>.md without identifiers; historical observation pages use YYYYMMDDHHMMSS-title.md without UUIDs or fractional seconds. Operation journals retain separate intent/result discriminators. Rebuild updates generated links and removes obsolete owned names; manual links need updates, while unmanaged notes remain untouched. Optional local collection_evidence 0.1.0 supplies the verified collection actor and per-query commands/states/reasons. Old records explicitly show missing evidence; rebuilding never reads raw results or reruns a host to fill it.

Host content lives under hosts/PRIMARY_GROUP/HOST/, where primary is the first configured membership; hosts without current membership use _ungrouped. Secondary groups link to the same host tree. The observation header is the host only, and the historical report’s final Collection metadata section combines account, source, time, title and query/provenance details. No success banner is added. Rebuild updates generated pages/links without moving unmanaged notes from old locations; see the canonical guide for required manual note/link actions. Equal-second/equal-title report collisions are explicit publication failures and never overwrite retained history.

The consumer rebuilds all current retained views on each event. Its writes replace owned Markdown outputs, remove stale owned pages and preserve unmanaged human notes. Repeated events safely rebuild current state through the existing ownership publisher. See [Vault paths, collision policy and verification limits](../../docs/host-vault.md). Publication is atomic per file, not across the whole Vault.

Disable automatic delivery with `consumers: {vault: {source: builtin:vault, enabled: false}}` or `vault: {auto_refresh: false}` in feast.yaml. Other consumers remain independent. Initialize/rebuild output with `python -B tools/opsfeast.py vault rebuild --profile main --json`; inspect/retry events with `consumers inspect` and `consumers dispatch vault`. Rendering or ownership failures leave retention committed and a retryable delivery receipt. Enabling after a disabled period processes matching journal backlog.

To add another content application, declare a separate consumer and source, use its own output location/ownership and enable it explicitly. Do not add per-application branches to runner or retention storage. Synthetic tests verify dispatch integration, replay, ownership and repeated output; no external hosting or native access evidence is implied.

Current records use records/current-<title>.md, contain data and a Latest report link, and omit Collection metadata. Both current and historical observation pages start with a Contents index; only historical reports end with Collection metadata, including identity/coverage warnings and queries. The redundant Field observations table is removed. Missing sections say No data was collected; observed empty collections remain No entries reported. Read structured retention records for original field states and timestamps. Rebuild regenerates owned pages without collecting again or rewriting retention; old manual links require deliberate updates. Current title collisions across sources fail publication without overwriting evidence.

Current selection groups each host by origin namespace, recipe-source qualifier (the prefix before a colon, or the unqualified source) and stable recipe ID, then selects the whole record with the greatest (observed_at, record_id). Recipe-directory moves within that source therefore keep one current page without aliases or rewriting historical references. Partial results remain partial. Distinct sources, origin namespaces or recipe IDs remain independent; a shared output title still fails publication explicitly rather than silently replacing another dataset. All historical reports remain available.

Vault Contents links use Obsidian-native heading fragments: `[System](#System)` and `[Collection metadata](#Collection%20metadata)`. Heading case is preserved and spaces/non-ASCII text are URL-encoded; arbitrary HTML anchor IDs are not used. Repeated headings are given unique readable titles (for example Services details) so each link reaches one section. In Obsidian Reading view, click a Contents link; in Live Preview, use the normal follow-link gesture (Cmd-click on macOS or Ctrl-click on Windows/Linux). Other Markdown readers can use different heading-fragment conventions; this is not a universal reader-compatibility guarantee. Rebuild regenerates current and historical observation pages plus the records index from retention, without recollection. See [Obsidian internal links](https://obsidian.md/help/links).
