# Recipe flow conformance and receiving-agent handoff

Status: design acceptance contract 0.1.0. Read
[architecture](recipe-flow-design.md), [language](recipe-flow-language.md) and
[case](recipe-flow-exchange-rate.md). These checks do not implement a runner or
authorize browser/host activity.

## What consistency means

For the same package/routine/runtime versions, bindings, frozen month and
normalized input snapshot, recipients must produce identical canonical data,
typed error, selected branch and permitted next action. Hash the same canonical
JSON representation for comparison: sorted keys, ensure_ascii=False,
allow_nan=False, separators (",", ":"), UTF-8 and no trailing newline.
Inputs must already conform to their declared JSON schemas. Human explanation wording may differ.
Different live acquisition times/providers can yield different snapshots; never
claim that a skill alone guarantees equal live observations.

No agent may regenerate the selector, infer a missing provider contract, silently
round a rate, broaden an input schema, or substitute a source/host to pass tests.
Schema, code and dependency changes create a new reviewed version and new
conformance evidence.

## Portable offline selector vectors

[quote-cases.json](examples/recipe-flow/quote-cases.json) carries a complete
normalized base table and cases. Each case replaces the named top-level table
fields in table_overrides; rows and coverage replace wholesale, not recursive
merge. target_month overrides the case month, otherwise use the file default.
expected is either an exact quote object or a typed error code.

The data uses synthetic April 2032 dates/prices. It is not a bank scrape,
transaction quote or preapproved parameter set. The vectors cover the 15th,
16th, 17th, ordering, currency, month boundaries, duplicates, headers, invalid
rates, date bounds and coverage. Their expected values are independently stated,
not generated by running the reference selector.

For authorized local documentation verification only, use the reference
selector fence (ordinary pure Python) from the case, never its virtual plan:

~~~sh
python -B - <<'PY'
from copy import deepcopy
import json
from pathlib import Path

case = Path("docs/recipe-flow-exchange-rate.md").read_text()
reference = case.split("## Reference selector for review and offline vectors", 1)[1]
code = reference.split("~~~python\n", 1)[1].split("\n~~~", 1)[0]
namespace = {}
exec(compile(code, "reviewed-reference-selector", "exec"), namespace)
vectors = json.loads(Path("docs/examples/recipe-flow/quote-cases.json").read_text())
for vector in vectors["cases"]:
    table = deepcopy(vectors["base_table"])
    table.update(deepcopy(vector.get("table_overrides", {})))
    month = vector.get("target_month", vectors["target_month"])
    try:
        actual = {"quote": namespace["select_monthly_usd_quote"](table, month)}
    except namespace["QuoteError"] as error:
        actual = {"error": str(error)}
    assert actual == vector["expected"], (vector["id"], actual, vector["expected"])
print("Passed", len(vectors["cases"]), "synthetic selector vectors")
PY
~~~

This command executes reviewed documentation utility code solely against
synthetic local data. It performs no browser acquisition, host connection,
recipe import or remote action. Review changes to that code before execution.
The plan is never passed to exec. This test is not a future runtime validator,
signature verifier, browser parser test or independent agent interoperability
proof.

## Non-selector acceptance scenarios

| Scenario | Required result |
| --- | --- |
| Browser tool absent | waiting_provider; no HTTP/source fallback, no SSH |
| Browser challenge | waiting_human; preserve state; never fabricate table |
| Incomplete DOM/pagination | coverage_incomplete; no quote or remote action |
| Changed merged headers | schema_changed; no guessed column mapping |
| Same quote with valid complete-policy grant | Continue under that grant; no redundant approval |
| Quote exceeds an explicit grant constraint | waiting_authorization; never adjust the rate |
| Receiver has no private host binding | Not ready; no source host/credential copied by default |
| Operand missing or conversion fails | condition_error; never select else as if false |
| Plan refers to an undefined call | Not ready; no per-agent implementation invented during execution |
| A package/routine/resource hash differs | Integrity failure; no activation or execution |
| Unsupported language/provider/schema version | Compatibility failure; no silent downgrade |
| Import contains an executable instruction | Treat as untrusted candidate data; no automatic execution |
| Same business key is running | Refuse a competing dispatch; show existing attempt |
| Action timed out after dispatch | outcome_unknown; no automatic retry |
| Process restarts after intent but before acknowledgement | Reconcile possible dispatch; never assume unstarted |
| Stop during remote action | Prevent dependents; record request/termination/cleanup separately |
| Exit 0 without business postcondition | command_completed, business outcome unverified |
| Retention or notification delivery fails | Preserve separate receipt; do not relabel original action |
| Import old execution records | Historical evidence only; no replay or new grant |

These scenarios are acceptance requirements to implement/test, not claims that
a runtime currently enforces them. Concurrency/lease tests must use the future
shared journal service, not a local Python dictionary.

## Receiving-agent protocol

1. Read the exported package's entrypoint and carried language/step contracts.
   Identify exact source/version/digests and installed versus merely readable skill
   copies. If the origin chat is needed, report the package as incomplete.
2. State the purpose, numbered path, typed inputs, private bindings, capabilities,
   effects and unresolved business postcondition without connecting anywhere.
3. Inspect payload/dependency closure and supported contracts. Do not import code,
   install packages or invoke a live case to discover their meaning.
4. Under explicit offline-test scope, run the pinned reviewed utility against
   the carried synthetic vectors; compare exact expected outputs/error codes.
   A recipient lacking the required interpreter reports unsupported, not guessed
   expected success.
5. Walk the non-selector cases as design review and identify requirements that
   need machine/provider/native tests. Write a structured review receipt.
6. Mark ready only when all required capabilities, bindings, reviewed effects,
   utilities and enforcement mechanisms exist. Actual execution additionally
   needs the corresponding human grant.

The review receipt identifies recipient agent/tool/runtime versions, package and
fixture digests, each observed/passed/failed/not_tested check, unresolved items,
scope of authority and readiness. Expected outcomes copied from a table are not
observed results. Manual reasoning is not evidence of machine enforcement.

## Independent-agent acceptance

Give at least two independently operating recipient agents only the closed
candidate package, common offline inputs and explicit read/offline-test scope.
Do not give them the originating conversation, a worked answer, browser cookies,
live credentials or shared in-progress conclusions. Compare canonical quotes,
errors, branch choices, stop points and proposed commands; retain both receipts.
Use synthetic hosts/paths so no live action is needed.

A divergence blocks the portability claim. Diagnose missing semantics,
routine/runtime drift, acquisition differences or a faulty recipient; revise the
package/specification and rerun affected checks. Do not choose the preferred
answer by majority vote. No independent-agent trial was performed for this
documentation delivery.

## Verification levels and implementation gates

| Level | Evidence required |
| --- | --- |
| Documented design | Discoverable specification/skill, explicit availability and complete case |
| Offline selector | Exact reviewed utility plus synthetic vectors pass |
| Portable package | Real manifest/dependency/schema/contract validation and import rejection tests |
| Agent interoperability | Independent recipient trials with compared receipts |
| Native acquisition/action | Authorized browser extraction, SSH identity/cleanup and business postcondition tests |

This delivery can establish the first two only. Native browser observations made
during earlier design discussion do not establish a browser adapter or end-to-end
execution. The current recipe packer/runner remain unchanged.

Before product implementation, deliver public tests for path traversal and
resource bounds; changed/missing dependencies; condition typing; branch
selection; grant reuse/rejection; business-key concurrency; crash points; unknown
outcomes; redaction; cancellation; retained evidence and import without actions.
Update [capability discovery](agent-capabilities.md), the recipes/flow skills,
CLI/API references and human Web guidance together with implemented interfaces.
